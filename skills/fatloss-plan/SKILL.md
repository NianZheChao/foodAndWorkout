# 规划（fatloss-plan）

**定位工作区**：工作区是包含 `README.md`（格式契约）、`scripts/nutrition.py` 与 `records/` 的目录树，默认就是当前工作目录。不确定时先找 `scripts/nutrition.py`；找不到就问用户要路径。**不要把任何绝对路径写进文件或命令。**

**命令由你执行，用户不会手敲。** 在工作区根目录用相对路径运行 `python scripts/nutrition.py ...`。若当前目录不是工作区根目录，用 `python <工作区路径>/scripts/nutrition.py ...`——脚本按自身位置定位工作区，从任何 cwd 都能正常运行。

输入是 `profile.md`（约束）、`targets.md`（目标）、`records/`（历史）。

## 先取数据

```bash
python scripts/nutrition.py trend --days 14    # 体重趋势、达标率、各肌群周组数
python scripts/nutrition.py totals --write     # 今天已摄入多少、还差多少
python scripts/nutrition.py lookup <食材>       # 食材换算
```

再读 `profile.md` 里的伤病禁忌、忌口过敏、大致库存（食材与调味料）、可用器材、每餐可投入时间。

## 推荐训练

按优先级：

1. **恢复优先**：同一肌群距上次训练不足 48 小时的排除，不推荐。
2. **补欠账**：用 `trend` 输出的各肌群周组数，优先练低于 `targets.md` 里 `weekly_sets_per_muscle` 的肌群。
3. **渐进超负荷**：查该动作最近一次的 `组x次x重量`，给出具体推进量——加重量（+2.5kg）或加次数（+1~2 次）；久未训练的部位维持上次重量重新适应。
4. **约束**：只用 `profile.md` 里可用的器材；有伤病时避开对应动作并给替代（如腰痛不做硬拉，改臀桥/腿弯举）。
5. **容量**：每次 4-6 个动作、每个 3-4 组，总时长对齐 `targets.md` 的"每次时长"。

输出：动作清单（动作 / 组x次 / 重量 / 目标 RPE）+ 预计时长 + 本次训练重点一句话。

## 推荐食谱

1. **先算缺口**：取 `totals` 的剩余热量与蛋白缺口，同时看钠是否已超标、纤维是否还缺。
2. **优先消耗 `profile.md` 里已有的食材与调味料**，尽量让用户不用额外采购。库存是"优先使用范围"而不是硬约束：
   - 库存表没写到的常见食材，不要自动当成"用户没有"，也不要假定他有。
   - 确实缺关键食材时，明确说清"买什么、买多少"，并给出**不买也能做的替代方案**。
   - 调味料也要看：库里没有蚝油就换生抽+糖，没有黑胡椒就用蒜姜。
3. 只用 `profile.md` 里可用的器材，控制在"每餐可投入时间"内。
4. **逐个食材列出克数**，热量与宏量必须用 `foods.csv` 的数值算出来，并给出这一餐的合计。不要凭感觉写数字。
5. 优先补齐蛋白；剩余热量用碳水填；纤维不足时加蔬菜；钠已超标就少放酱油类调料。
6. 尊重忌口与过敏，不推荐 `dislikes` 里的食材。

输出：食材克数表 + 四项营养合计 + 与缺口的对比。若用到库存之外的食材，单独列一行"需要补货"。

用户口头提到"买了 / 用完了 / 还剩"时，顺手更新 `profile.md` 的两张库存表——它只是大致范围，不需要精确。

## 周计划

1. `python scripts/nutrition.py week` 取 ISO 周编号与起止日期。
2. 按 `templates/weekly-plan.md` 写入 `plans/YYYY-Www.md`。
3. 内容：本周训练日程（日期 / 肌群 / 主要动作 / 组数）、每日热量与蛋白目标、备餐思路、风险与预案。
4. 周计划只安排**训练结构与饮食策略**。具体到每一餐的食谱在当天再用上面的"推荐食谱"算——缺口每天都不一样。

## 边界

- 数据不足时（如只有 1-2 天记录）直接说明，不要假装能看出趋势。
- 饮食建议保持在 `targets.md` 的目标范围内；要修改热量目标交给 `fatloss-review`。
- 不承诺具体减重数字；不确定的地方标为建议而非结论。
