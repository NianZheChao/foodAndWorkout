# 记录（fatloss-log）

**定位工作区**：工作区是包含 `README.md`（格式契约）、`scripts/nutrition.py` 与 `records/` 的目录树，默认就是当前工作目录。不确定时先找 `scripts/nutrition.py`；找不到就问用户要路径。**不要把任何绝对路径写进文件或命令。**

**命令由你执行，用户不会手敲。** 在工作区根目录用相对路径运行 `python scripts/nutrition.py ...`。若当前目录不是工作区根目录，用 `python <工作区路径>/scripts/nutrition.py ...`——脚本按自身位置定位工作区，从任何 cwd 都能正常运行。

动手前先读工作区的 `README.md` 与 `AGENTS.md`。

## 流程

1. 确定日期（默认今天），运行 `python scripts/nutrition.py new --date <日期>`。脚本是幂等的：文件已存在时不会覆盖，直接在原文件上补写。
2. 把用户的描述拆成结构化数据：每一餐**每个食材一行**，每个动作一行。`菜品/做法`列写清菜名与做法（如"香煎""清炒""红烧"），同一道菜的多个食材共用同一个值。
3. 换算营养：`python scripts/nutrition.py lookup <食材>`，或 `lookup <食材> --g <克数>` 直接换算。库中没有的食材先补进 `data/foods.csv` 并在 `note` 列注明来源。
4. 收尾：`python scripts/nutrition.py check` 通过后，运行 `python scripts/nutrition.py totals --write`。
5. 把汇总回报用户：直接贴脚本产出的表（摄入 / 目标 / 差额 / **占比**），再点出热量与蛋白的占比以及还差多少。占比由脚本算，不要自己另算，也不要为了简洁省掉这一列。
6. 同步：按 `README.md` 的「本地改动同步」把本次动过的文件（`records/<日期>.md`，必要时 `data/foods.csv`、`profile.md`）commit 并 push 到 GitHub（`log: <日期> <摘要>`）。冲突或推送被拒就停下报告，不要 `push --force`。
7. 缺口确认：同步后把当天仍空着的字段列给用户，问清每一项要以什么形式补（见下）。不要默默留空，也不要替他判断某项"不重要"。

## 收尾必做的缺口确认

每次录入结束、同步之后，用固定形态列出还空着的信息，**问用户要以什么形式给我**，而不是自行决定留空：

| 字段 | 建议怎么给我 |
| --- | --- |
| `weight_am_kg` | 晨起排尿后称一次报 kg；没称就说"没称" |
| `weight_pm_kg` | 睡前称一次，或者说不打算记 |
| `sleep_hours` | 报"几点睡到几点"，我换算成小时 |
| `energy` / `soreness` | 按 `README.md` 契约里的 1-5 口径报一个数 |
| 训练 `时长` / `RPE` | 报大概多少分钟；RPE 报"最后一组还能再做几次" |
| 摄入 | 报吃了什么，报多少记多少；记不清就说记不清 |
| 状态与备注 | 有异常（酸痛、饥饿、熬夜）说一句，我照原话记 |

规矩：

- 每次录入收尾都问一遍，**但用户明确说过"不记 / 没意义"的字段，此后不再追问**；他哪天主动提起再补。
- 饮水已停用，不在确认表里（见 `profile.md` 的「记录口径约定」）。
- 用户答不上来的，留空，不要替他估一个数，也不要用备注里的"假设"冒充数据——两者是两回事。
- 同一次对话里不重复问同一件事；已在别处给过的口径（如 `profile.md` 里的约定）直接沿用，不再确认。

## 体重与训练的分栏

- 体重填两栏：`weight_am_kg`（晨起空腹、排尿后）是趋势与 TDEE 的唯一基准，`weight_pm_kg`（睡前）只用于算夜间净流失。用户只称了一次就只填一栏，**不要把睡前值填进晨重**。
- 用户报体重的**默认口径就是晨起排尿后、空腹**（已确认）。按此直接记入 `weight_am_kg`，不必每次追问"排没排尿"，也不必在备注里重复说明；只有口径偏离默认时（睡前、饭后、运动后、非空腹）才写进备注或改记 `weight_pm_kg`。
- 训练一行一个动作，`组x次x重量`必填：脚本用它算容量负荷，这是力量训练的主指标。**时长和 RPE 要主动问**——没时长算不出有氧消耗，没 RPE 判断不了强度；用户答不上来就留空，不要编。
- 报告时区分：有氧看热量（`MET × 3.5 × 体重 / 200 × 时长`），力量看容量负荷与每肌群组数，不要用"训练消耗"去冲抵热量目标。

## 换算要点

- 库中数值是每 100g 可食部。常见基准：鸡蛋 1 个 ≈ 50g，一碗米饭 ≈ 150g 熟饭，一勺油 ≈ 10g，一杯牛奶 ≈ 250ml。
- **做法带来的油、糖、酱料、淀粉必须单独成行。** 煎/炒至少按 5-10g 油估，红烧/糖醋还要加糖。这是漏记的主要来源。
- 生熟不能混用：生米 100g ≈ 熟饭 250g，库里的"米饭(熟)"按熟重记。
- 水煮的肉类会有一部分脂肪溶进汤里；如果汤不喝，如实记录全量并在备注里说明偏差方向，不要自行打折——口径不一致会污染后续的 TDEE 校准。
- 用户给重量就用重量；给个数先换算成克，并在备注里写明换算依据。
- 份量不明确时按常见值估并写明假设；**不要编造用户没吃过的食物**。

## 记录训练

- `RPE` 为主观强度 1-10。用户说"很累"记 8-9，"轻松"记 4-5，并把用户原话写进备注。
- `组x次x重量`形如 `4x8x60kg`；自重动作写 `3x12x自重`。脚本用它算容量负荷（组×次×重量，自重不计）；该列不符合格式时按 1 组统计并告警。
- `目标肌群`多肌群用 `/` 分隔，如 `胸/三头`。
- `估算消耗(kcal)` 用 MET 公式算：`MET × 3.5 × 体重(kg) / 200 × 时长(min)`（力量训练 MET 3-6，慢跑 7-9，快走 4.3），在备注里标明是估算值；**缺时长就留空**，不要凑数。

## 常见情况

- **一次报了好几天**：按日期分别建文件逐天写入，最后对每一天跑一次 `check`。
- **只报了部分餐次**：只写报上来的部分，不要顺手补全其余餐次。
- **不记得份量**：按常见值估并写明假设，方便下次修正。
- **描述模糊到无法拆分**（如"吃了顿大餐"）：先问清菜品与大致份量再录入，不要硬猜。
- **用户问"今天还差多少"**：属于推荐范畴，改用 `fatloss-plan`。
- **用户提到买了或吃完了某样东西**：顺手更新 `profile.md` 的库存表（食材 / 调味料）。那只是"优先使用范围"，写个大概即可，不要追问精确数量。
